# OLEDGuard

Mac mini に接続したモニター(最大3枚)のうち、選んだモニターだけに、一定時間操作がなかったときに待ち受け(画像・動画)を全画面で重ねて表示する、メニューバー常駐アプリ。有機ELモニターの焼き付き防止用。

チャットアプリなどを常に表示しているモニターでも、開いているアプリの上に待ち受けを重ねるので、壁紙やスクリーンセーバーと違い、そのモニターだけを守れる。

## 必要なもの

- macOS 27 以降(Mac mini で動作確認)
- コマンドラインツール(`xcode-select --install`)の Swift 6 以降。Xcode は不要

## ビルドと起動

ターミナルでこのフォルダに移動してから実行する。

| コマンド | 内容 |
|---|---|
| `make run` | アプリを作って起動する(起動中のものは終了させてから) |
| `make run-debug` | 確認用。「1分」を6秒として扱って起動する(5分設定なら30秒で待ち受け) |
| `make test` | ユニットテストを実行する |
| `make app` | `build/OLEDGuard.app` を作るだけ(swift build + ad-hoc 署名) |
| `make stop` | 起動中のアプリを終了する |

最新のコードを取り込むときは `git pull` してから `make run`。

待ち受けまでの時間の短縮は、起動引数 `--minute-seconds 秒数` か、環境変数 `OLEDGUARD_MINUTE_SECONDS=秒数` でも指定できる。短縮中は設定画面の上にオレンジ色で表示される。

## 使い方

メニューバーの月のアイコンから操作する。

- **一時停止 / 再開**: 一時停止中はすべてのタイマーを止め、待ち受けも出さない。再開すると最初から数え直す(一時停止は保存しない。起動し直すと解除)
- **設定を開く…**
- **今すぐテスト表示**: 「待ち受けを使う」がオンのモニターすべてに、時間を待たずに待ち受けを出す
- **終了**

### 設定画面

モニターごとに次を設定する。設定はモニターの UUID ごとに保存され、つなぎ直しや再起動をしても同じモニターに残る。接続していないモニターの設定も「未接続のモニター」として残る(不要なら削除できる)。

- **待ち受けを使う**: オン/オフ
- **待ち受けまでの時間**: 5、10、15、20、30、40、50、60 分
- **ファイル**: 画像(JPEG / PNG / HEIC / PDF)または動画(MP4 / MOV / M4V)。サムネイルが出る
- **表示方法**: フィル(画面全体を覆う)/ フィット(全体が見え、余白は黒)
- **状態**: 待ち受けまでの残り時間など
- **今すぐテスト表示**: そのモニターだけに待ち受けを出す

「ログイン時に自動起動」をオンにすると、ログイン時に起動する(システム設定 > 一般 > ログイン項目)。

設定ファイル: `~/Library/Application Support/OLEDGuard/settings.json`

## 動作のしくみ

- **無操作の判定はモニターごと**: 対象モニターの範囲内でマウスカーソルが動いた、またはクリックしたときだけ、そのモニターのタイマーを最初に戻す。他のモニターでの操作やキーボード入力は関係しない。カーソルが対象モニター上にあっても、動かなければ無操作とみなす。
- カーソル位置は1秒ごとに確認する。クリックは macOS のマウスイベントの監視で受け取る。どちらもアクセシビリティなどの許可は不要。
- **待ち受け**は、対象モニターだけを覆う枠なしのウィンドウ。メニューバー・Dock・全画面アプリより前面に、どの Space にも出る。背景は黒。
- **解除**は待ち受けのクリックだけ。クリックは待ち受けが受け取り、下のアプリには届かない。キー入力は元のアプリに届いたまま。解除後、そのモニターのタイマーは最初から数え直す。
- スリープ、画面ロック、ユーザー切り替え、ディスプレイ構成の変更(抜き差し・配置変更)のときは、待ち受けを閉じる。スリープ・ロックの間は判定を止め、戻ったら全モニターを最初から数え直す。
- ファイル未選択、またはファイルが見つからないときは、黒画面の待ち受けを出す(設定画面には警告)。
- 読み込み・再生に失敗したとき(壊れたファイル、デコードできないコーデックなど)は、待ち受けを出さずに設定画面に警告を出す。再生途中で失敗した場合も、閉じて警告を出す。
- 画像は ImageIO で画面の解像度まで縮小して読み込む。PDF は1ページ目を画面の解像度で描画する。
- 動画は AVQueuePlayer + AVPlayerLooper で、音なしでループ再生する。ファイルは必要な分だけ読みながら再生し、デコードは macOS 標準のハードウェアデコードに任せる。待ち受けを閉じると再生を止め、プレイヤーを解放する。動画を流していても、macOS のディスプレイスリープは妨げない。

参考値(WUXGA モニター1枚で動画を再生中): OLEDGuard の CPU 3〜4%。閉じると数秒で 0% に戻る。GPU と動画のデコードは、アクティビティモニタ上では WindowServer などの別プロセスに計上される。

## 既知の制限

- 操作として数えるのは「カーソルの移動」と「クリック」だけ。カーソルを動かさないスクロール(ホイール、トラックパッドの2本指スクロール)や、キーボード入力では、タイマーは戻らない。
- カーソル位置は1秒ごとの確認なので、1秒以内に動いて元の位置に戻った場合は、操作として数えない。
- 待ち受けの上でもマウスカーソルは見えたまま。
- モニターの識別は macOS が返す UUID に頼っている。変換アダプタやつなぐポートを変えると別のモニター扱いになることがあり、その場合は設定し直しが必要(古い設定は「未接続のモニター」に残る)。
- ミラーリング中のモニターは1枚として扱う。
- 「ログイン時に自動起動」は、登録したときの `build/OLEDGuard.app` の場所に結びつく。フォルダを移動した場合は、一度オフにしてからオンにし直す。
- 開発上の注意: コマンドラインツールだけの環境では、SwiftUI のマクロ(`@State` など)と XCTest が使えない。設定画面の状態は `ObservableObject` に持たせ、テストは自前の小さな仕組み(`Tests/OLEDGuardCoreChecks`)で実行している。

## 今後の拡張案

- 通知と連携した自動解除(チャットアプリに新着があったら待ち受けを閉じる)
- 画面の変化の検知(対象モニターの表示内容が変わったら操作とみなす。画面収録の許可が必要になる)
- スクロールを操作として数えるオプション
- 待ち受け中のカーソル非表示
- 時間帯による有効/無効のスケジュール
- 複数の画像・動画を順番に表示

## 構成

```
Sources/OLEDGuardCore/      UI に依存しないロジック(設定モデル、保存、無操作判定 IdleTracker)
Sources/OLEDGuard/
  App/                      起動、メニューバー、アプリ全体の状態
  Displays/                 接続中モニターの一覧と変化の検知
  Idle/                     IdleTracker に実際のカーソル位置・クリック・時刻を渡す IdleMonitor
  Overlay/                  待ち受けウィンドウ、画像/PDF の読み込み、動画再生
  Settings/                 設定画面、設定の保存、自動起動、サムネイル
Tests/OLEDGuardCoreChecks/  ユニットテスト(make test)
scripts/build-app.sh        .app の組み立てと ad-hoc 署名
```
